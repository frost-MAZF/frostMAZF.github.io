gitlab安装及配置

发表于2026-09-14|更新于2026-09-14|计算机网络版本管理
|总字数:1.1k|阅读时长:3分钟|浏览量:

前言

很多时候只不过是想在随便和朋友玩玩一个项目，又不想上传到GitHub，只不过是在本地搞搞，于是就动了搭建一个gitlab-ce的心思，配置很麻烦，但是即便是搭建一个gitlab也玩的很开心。

前置准备

要搭建一个gitlab-ce（下面简称gitlab），我们有两种方案，一个是通过一台本地设备安装gitlab，经过公网IP或者内网穿透来互相连接，另一个则是通过一台服务器安装gitlab，第一个方案需要那台设备经常在线，于是便选择第二种。

  • 一台公网IP服务器
  • 一个域名

其实这个域名不要也可以，只需要在输入域名的时候输入IP即可。

安装gitlab-ce

进入到服务器的后台后，我们输入安装curl：

sudo apt update
sudo apt install -y curl

接着使用脚本添加gitlab仓库：

curl --location "https://packages.gitlab.com/install/repositories/gitlab/gitlab-ce/script.deb.sh" | sudo bash

然后安装gitlab-ce，这里的EXTERNAL_URL里需要修改成自己的域名，域名需要在DNS里添加一个A记录指向你的服务器公网IP。

此外，你还可以添加GITLAB_ROOT_EMAIL来设定你的root邮箱，GITLAB_ROOT_PASSWORD来设定你的root密码

sudo EXTERNAL_URL="https://gitlab.example.com" apt install gitlab-ce

接着我们登录gitlab，用户是root，密码是你设定好的密码，或是需要查看：

cat /etc/gitlab/initial_root_password

接着我们就可以创建账号和仓库了，这点和其他版本的gitlab没有差别。

配置SMTP来给新用户发送验证邮件

这里具体可以查看gitlab文档，根据自己的喜好选择SMTP服务商即可，这里就选择gmail了。

根据文档，我们首先需要增加一个两步验证器，这里可以用ente auth

接着我们需要创建一个应用密码，相当于是令牌的东西，很简单，将显示出来的密码复制即可。

接下来就是gitlab的设置，我们首先需要修改一下配置文件：

sudo vim /etc/gitlab/gitlab.rb

然后将下列的配置取消注释，并写上你自己的配置，这里的password是需要填写应用密码的。

gitlab_rails['smtp_enable'] = true
gitlab_rails['smtp_address'] = "smtp.gmail.com"
gitlab_rails['smtp_port'] = 587
gitlab_rails['smtp_user_name'] = "my.email@gmail.com"
gitlab_rails['smtp_password'] = "my-gmail-password"
gitlab_rails['smtp_domain'] = "smtp.gmail.com"
gitlab_rails['smtp_authentication'] = "login"
gitlab_rails['smtp_enable_starttls_auto'] = true
gitlab_rails['smtp_tls'] = false

## 如果没有则自行添加下面这行
gitlab_rails['smtp_openssl_verify_mode'] = 'peer' # Can be: 'none', 'peer', 'client_once', 'fail_if_no_peer_cert', see http://api.rubyonrails.org/classes/ActionMailer/Base.html

## 下面的是邮件设置
gitlab_rails['gitlab_email_enabled'] = true
gitlab_rails['gitlab_email_from'] = 'gtlab@example.com'
gitlab_rails['gitlab_email_display_name'] = 'GitLab'

在保存完成后输入下面的命令来重新载入配置：

gitlab-ctl reconfigure

配置GitLab Runner以使用CI/CD

配置GitLab Runner的原因主要是将静态网页运行起来。
这里是文档

首先下载脚本并运行：

curl -L "https://packages.gitlab.com/install/repositories/runner/gitlab-runner/script.deb.sh" -o script.deb.sh | sudo bash script.deb.sh

然后便可以安装GitLab Runner了：

sudo apt install gitlab-runner

接着我们需要注册一下Runner，首先进入到我们的项目页面，接着点击左侧的设置，然后CI/CD，然后在Runner下点击创建Runner。

这里的标签也是可选的，只需要勾选运行未打标签的作业即可。

最后我们回到我们的服务器后台，输入显示出来的命令即可，例如：

gitlab-runner register  --url http://gitlab.example.com  --token 123456789

启用Pages并部署网页

首先需要修改一个gitlab配置。

sudo vim /etc/gitlab/gitlab.rb

将下面的配置取消注释并换成你的配置：

pages_external_url "http://gitlab.example:12345/"
gitlab_pages['enable'] = true
gitlab_pages['namespace_in_path'] = true
pages_nginx['enable'] = true

接着我们就可以重新载入一下配置，然后就可以在项目左侧的选项栏下，在部署中找到Pages了

gitlab-ctl reconfigure

gitlab主要使用.gitlab-ci.yml，具体可以查看CI/CD YAML syntax reference和CI/CD examples来学习如何使用。

例如，我用来运行Hexo的.gitlab-ci.yml文件是这样的：

image: docker.1ms.run/library/node:26.8.2-alpine
cache:
  paths:
    - node_modules/

before_script:
  - npm install hexo-cli -g
  - test -e package.json && npm install
  - hexo generate

pages:
  script:
    - hexo generate
  artifacts:
    paths:
      - public
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
